# スマホ・WatchのLRC歌詞

Reader 0.2.6 / Wear 0.2.4で、音声と同じ名前の `.lrc` を読み、再生位置に合わせて現在の行と前後の歌詞を表示する。動画の字幕・Watch動画再生は対象外。

## 置き方と操作

音声の実ファイルと同じフォルダに、拡張子だけを変えた歌詞ファイルを置く。

```text
曲名.mp3
曲名.lrc
```

EAGLEライブラリでは通常 `*.library/images/<ID>.info/` が実ファイルのフォルダになる。EAGLE画面の分類フォルダに別アイテムとしてLRCを登録する方法は、この物理的な隣接配置とは異なる。元の音声、metadata.json、ライブラリ構造をアプリが書き換えることはない。

- スマホ: 音声の再生画面に歌詞を表示する。再生中にLRCを編集したときは「歌詞を更新」で読み直す。歌詞の通信失敗で音声再生は止めない。
- Watch: スマホのライブラリ側から「選んだ曲をWatchに保存」で音声と歌詞を保存する。Watchの受信を終了し、曲を再生して「歌詞」を押す。保存後はスマホやDriveに接続せず表示できる。戻ると従来のシーク・音量画面を使える。
- 歌詞だけの追加・変更・削除も、ライブラリ側から同じ保存・送信操作で反映する。音声が同じなら再ダウンロード・再転送しない。本棚の「更新」や「更新あり」の判定は音声索引用であり、それだけで保存済み歌詞は更新されない。
- 「スマホに保存済み」からの再生・送信は、保存済みの歌詞を使う。この画面からの「歌詞を更新」は端末内コピーを読み直す。元のLRC変更を取り込むにはライブラリ側から保存し直す。
- 旧カタログのDrive API音声は元の親フォルダを取得できる。端末フォルダ/Drive Providerの旧カタログは、本棚を一度更新してから利用する。
- 保存時の歌詞取得に失敗したらエラーを表示し、以前の歌詞を保持する。音声本体が先に保存できている場合はそれも保持し、再試行時に省略する。失敗を「歌詞削除」として送信しない。

ファイル名の本体は大文字小文字も含めて一致させる。拡張子は `.lrc` / `.LRC` に対応する。同じ名前が複数ある場合は曖昧な選択を避けてエラーを表示する。別名のLRCを自動選択しない。

## LRC形式

UTF-8（BOM任意）、BOM付きUTF-16 LE/BE、最大64 KiB。例は動作確認用のテキスト。

```lrc
[ti:動作確認]
[offset:0]
[00:01.00]最初のテスト行
[00:04.500]次のテスト行
[00:08.00]
```

`[mm:ss]` と小数1～3桁、同じ行の複数時刻、並び替え、同時刻の翻訳行を扱う。空の時刻行は歌詞を消す。`[offset:+500]` は500 ms早く、負数は遅く表示する。1ファイル最大4,000時刻、offsetは±24時間まで。時刻なしのテキストはスクロールして読める。メタデータと不正な時刻タグは歌詞として表示しない。文字単位のカラオケ強調（Enhanced LRC）や自動文字コード推定は対象外。Shift-JISのファイルはUTF-8で保存し直す。

## 保存・互換

両アプリの専用領域 `offline-audio-v1/lyrics/<key>-<revision>.lrc` に原文を保存する。音声のv1カタログ・音声ハッシュ・同期対象チェックは変更しない。歌詞は音声容量の表示/上限とは別枠で、1曲64 KiB以内。曲の明示削除時に対応する歌詞も削除し、他の曲や元のLRCには触れない。歌詞更新は一時ファイルの置換で確定し、中断時には前の版を保持する。

Data Layer v3 capability/channelを追加。v3ヘッダーは最大128 KiB（歌詞最大64 KiB、画像最大16 KiBのBase64込み）。受信側は検証済み音声が既にある場合も歌詞を更新してから `stored` を返す。v3のnull歌詞は確認済みの削除。保存失敗なら成功応答を返さず再送できる。

v1/v2の音声転送・v2画像は引き続き受信する。旧スマホからはWatchの既存歌詞を削除しない。新スマホから旧Watchへの音声転送は従来形式を使い、歌詞対応のWatch更新が必要だと案内する。APK署名とpackage nameは従来と共通。
