# Phone file cache

After the user starts a library update in the foreground and its index is saved successfully, the Reader keeps an app-private copy of every eligible indexed file in that EAGLE library. It covers indexed primary files and thumbnails for image, audio, and video entries, including files hidden by the current folder, tag, or search filter. It does not run a background index/update. Lyrics are not EAGLE index assets; matching LRC siblings are cached separately as a bounded 64 KiB sidecar.

All files are included by default. Open **端末キャッシュ** from the bookshelf to search the whole library and turn individual files off or back on. The setting belongs to that library, is written to the saved state, and remains in place across re-indexing. Turning a file off stops future automatic updates but does not delete a saved copy. Turning it back on makes it eligible on the next library update.

The files live in the app-private phone-file-cache-v1 directory. The original library remains read-only. Each copy is keyed by its provider identity and the indexed metadata stamp, provider file timestamp, size, extension, and URI. Known lengths are checked; new bytes are written to a temporary file and switched into place only after the complete read and local validation. A newer indexed revision replaces the old revision for that item. Unchanged revisions reuse the existing bytes. Lyrics keep the previous validated bytes until a new sidecar has been validated and the manifest points to it; confirmed deletion invalidates the prior lyrics.

The index metadata and later file read are separate provider operations, not an immutable snapshot. A provider can change a file after indexing and before its cache read; if the replacement has the same length and the provider exposes no revision token, the fetched bytes may not be provably identical to the indexed revision. The cache validates complete local reads and known lengths, but does not re-query every remote item or use a conditional ETag. The next foreground library update rechecks provider metadata.

The automatic cache has no per-file cap or user-configurable total quota. It checks available device space and reserves at least 16 MiB while writing. A storage-wide or authentication failure stops the pass and is shown in the sync result; an individual unavailable file is reported while the other files continue. Cancel stops the current pass, keeps completed items and retries remaining eligible items on the next update. A source entry that the indexer could not verify is skipped and remains eligible for a later retry.

Playback, thumbnails, and lyrics use only a cache revision matching the current indexed asset. If a new revision could not be saved, an older physical copy is retained as last-good data but is not presented as the current source. Ordinary browsing can then read the provider source or show its read error. Normal cache entries are independent of offline-audio-v1 and Watch targets: saving, removing, or selecting explicit offline audio does not change ordinary cache preferences or files. The phone cache and explicit offline audio payloads are excluded from Android cloud backup and device transfer; the small library index and per-file exclusion preferences remain in the app state.
